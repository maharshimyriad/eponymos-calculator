## 3. Stated spend is ignored when no tools are selected

**Reported issue:** A prospect who says they spend $5,000-plus a month and selects no tools ends up with a current software cost of $0. The reported spend answer is discarded in favour of the empty tool list.

**Why this happens in code:** Stage 2 currently treats the selected competitor tool total as the software-spend baseline. When no tool is selected, the numeric total stays at zero because there is no separate, wired spend field in this code path to act as a fallback.

**Decision needed:** confirm whether the questionnaire should store and use a direct “current monthly software spend” value as the fallback when no tools are selected, or whether zero is intentionally accepted for empty-tool cases.

**Impact:** As implemented, the spend question appears redundant and the report can lean on productivity assumptions as the only value line when no competitor tools are selected.

**Fixability from our side:** not without a product decision and a data field. If the client wants to preserve the stated spend answer, we need a dedicated spend question or server-side input mapped to the calculation; otherwise the plugin cannot infer it reliably from the current tool list alone.

## 4. Test mode does not protect external testers

**Completed:** A dedicated “test email allowlist” is now configured directly beneath the test-mode toggle. Default QA addresses are `blahblah@blahblah.com` and `test@email.com`. Any submission from these addresses is treated as a non-persisted test submission: no database entry, no notification email, and no lead generation, while the rest of the questionnaire flow still runs normally for comparison/calculation purposes. The PDF is generated using the tester's submitted email and is available through a signed download link; Stage 2 regenerates the PDF with the latest answers rather than reusing a Stage 1 copy.

**Why this happens in code:** The previous gate was tied to `current_user_can('manage_options')` and the administrator-only test-mode toggle in [includes/Questionnaire/Shortcode.php](includes/Questionnaire/Shortcode.php) and [includes/REST/Routes.php](includes/REST/Routes.php). That meant a tester using a normal public email still passed the regular submission flow and created a live submission record.

**Design note:** This is enforced before the save path and before notification dispatch by checking the submitted email against the allowlist. The save repository already rejects test-mode submissions, and the REST layer already swaps in placeholder addresses for test-mode runs. Test PDF downloads use a signed URL and do not require storing a lead submission.

**Impact:** This prevents the QA team from polluting the lead table during manual testing without disabling all non-admin testing. Normal submissions still save unchanged for all other visitors.
